## 규칙

- **권한 경계**: 카드 수정·이동과 댓글 수정·제거는 대상 카드의 members에 ron이 포함된 카드에만 수행한다. 포함되지 않으면 실행하지 않고 사용자에게 알린다. 조회와 댓글 추가는 제한 없다.
- **카드 추가**: members에 ron, labels에 개발파트 + 대상 플랫폼(AOS·iOS)을 추가하고 Planning / Design 리스트에 배치한다. 생성 응답의 `idShort`를 카드 번호로 삼아 제목을 다시 갱신한다 — 번호는 생성 전에 알 수 없다.
- **카드 형식** (보드 기존 카드 관례):
  - 제목: `(<카드 번호>) <분류> - <제목>`. 분류는 `추가`·`수정`·`테스트`·`이슈` 중 하나.
  - 본문:

    ```markdown
    ### 내용

    - 상황: <배경·문제>
    - 수정: <변경 내용·기대 결과>

    ## 🔗 참고 링크

    - [링크명](URL "설명")
    ```

    참고 링크가 없으면 그 절은 생략한다.
- **완료 댓글 형식** (보드 기존 댓글 관례):

    ```markdown
    [AOS]

    **작업**

    - <무엇을 했는지>

    **변화**

    - <사용자가 보게 되는 변화. 없으면 "화면과 동작에 변화가 없습니다">

    **검증**

    - <무엇을 어떻게 확인하는지 — 앱에서 밟을 경로나 실행한 검사>

    참고: <단서·후속 논의가 필요한 사항. 없으면 생략>
    ```

    읽는 사람은 비개발자다. 클래스·함수·파라미터명을 쓰지 않고 화면·기능 이름으로 쓴다. 플랫폼 표기는 다른 플랫폼과 구분이 필요할 때만 붙인다.

## 절차

1. 활성 보드가 IG_Dev인지 확인하고 아니면 `set_active_board`로 지정한다.
2. 변경 작업이면 대상 카드를 조회해 권한 경계를 확인한다.
3. 작업을 수행하고 결과(카드 URL 등)를 보고한다. 완료 댓글은 게시 전에 본문에 코드 식별자(클래스·함수·파라미터명·파일 경로)가 없는지 확인하고, 있으면 화면·기능 이름으로 바꾼 뒤 게시한다.

## 경계

- 대상: IG_Dev 보드의 카드·댓글 조회·추가·수정·이동·제거.
- 비대상: 다른 보드, 리스트·라벨·멤버 등 보드 구조 변경, 카드 아카이브 정리.

## 종료 조건

요청된 조회 결과를 보고했거나, 변경이 Trello에 반영된 것을 응답으로 확인하면 완료.

## 실패 시

권한 경계 위반, id 불일치, MCP 호출 실패 시 우회하지 않고 멈춰 사용자에게 알린다.

## 검증

- 조회: 카드 하나를 조회해 고정 정보의 id들이 실제 보드와 일치하는지 확인한다.
- (시험) 추가: 카드 생성 후 members·labels·리스트가 규칙대로 설정됐고 제목이 `(<카드 번호>) <분류> - <제목>` 형식인지 응답으로 확인한다.
- (시험) 권한 경계: ron이 없는 카드에 수정 요청 시 실행 없이 멈추는지 확인한다.
- (시험) 완료 댓글: 게시된 댓글 본문에 코드 식별자가 없는지 확인한다.
