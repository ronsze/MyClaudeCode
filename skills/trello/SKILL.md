# trello

목적: 프로젝트 보드의 카드·댓글 작업을 보드 규약에 맞게 수행한다.

보드 규약(보드·멤버·라벨·리스트 id, 카드 제목·본문 형식, 완료 댓글 형식)은 프로젝트 `.claude/trello.md`가 정본이다. 없으면 `${CLAUDE_SKILL_DIR}/references/trello.md`를 복사해 만들고 사용자에게 값을 받아 채운 뒤 진행한다 — 추측으로 채우지 않는다.

## 규칙

- **고정 정보**: `.claude/trello.md`의 id는 조회 없이 사용한다. 호출이 not found 등으로 실패하면 재조회해 맞추고 사용자에게 보고한다.
- **권한 경계**: 카드 수정·이동과 댓글 수정·제거는 대상 카드의 members에 담당 멤버(`.claude/trello.md`)가 포함된 카드에만 수행한다. 포함되지 않으면 실행하지 않고 사용자에게 알린다. 조회와 댓글 추가는 제한 없다.
- **카드 추가**: `.claude/trello.md`의 기본 members·labels·리스트를 설정한다. 카드 번호를 제목에 쓰는 규약이면 생성 응답의 `idShort`로 제목을 다시 갱신한다 — 번호는 생성 전에 알 수 없다.
- **카드·완료 댓글 형식**: `.claude/trello.md`의 형식을 그대로 따른다. 완료 댓글의 독자는 비개발자다 — 클래스·함수·파라미터명·파일 경로를 쓰지 않고 화면·기능 이름으로 쓴다.

## 절차

1. 활성 보드가 `.claude/trello.md`의 보드인지 확인하고 아니면 지정한다.
2. 변경 작업이면 대상 카드를 조회해 권한 경계를 확인한다.
3. 작업을 수행하고 결과(카드 URL 등)를 보고한다. 완료 댓글은 게시 전에 본문에 코드 식별자가 없는지 확인하고, 있으면 화면·기능 이름으로 바꾼 뒤 게시한다.

## 경계

- 대상: 프로젝트 보드의 카드·댓글 조회·추가·수정·이동·제거.
- 비대상: 리스트·라벨·멤버 등 보드 구조 변경, 카드 아카이브 정리.

## 종료 조건

요청된 조회 결과를 보고했거나, 변경이 Trello에 반영된 것을 응답으로 확인하면 완료.

## 실패 시

권한 경계 위반, id 불일치, MCP 호출 실패 시 우회하지 않고 멈춰 사용자에게 알린다.

## 검증

- 템플릿: `.claude/trello.md`의 절 구성이 `references/trello.md`와 같은지 확인한다.
- 조회: 카드 하나를 조회해 고정 정보의 id들이 실제 보드와 일치하는지 확인한다.
- (시험) 추가: 카드 생성 후 members·labels·리스트가 규약대로 설정됐고 제목이 규약 형식인지 응답으로 확인한다.
- (시험) 권한 경계: 담당 멤버가 없는 카드에 수정 요청 시 실행 없이 멈추는지 확인한다.
- (시험) 완료 댓글: 게시된 댓글 본문에 코드 식별자가 없는지 확인한다.
