# harness

목적: 하네스 구성요소가 아래 원칙과 배치 기준을 따르도록 추가·제거·수정·검토를 수행한다.

## 원칙

### 제1원칙 — 목적이 있어야 한다

- 구성요소의 본문 또는 스크립트 최상단에 목적을 주석(또는 첫 문장)으로 서술한다.
- 목적은 모호하지 않고 간결하게 완결돼야 하며, 하나의 구성요소는 복수의 목적을 가지지 않는다.
- 목적을 서술할 수 없으면 구성요소로 추가하는 것을 재고한다. 목적이 다른 구성요소와 겹치면 병합 또는 확장을 고려한다.
- 기존 구성요소의 description·본문으로 표현할 수 없는 이유를 한 문장으로 대지 못하면 추가하지 않는다.

### 제2원칙 — 필요한 문장만 쓴다

- 문장마다 판정한다: **이 문장이 없을 때 나오는 잘못된 산출물을 하나 댈 수 있는가.** 대지 못하면 지운다. 댈 수 있으면 그 사례를 검증 항목으로 옮긴다.
- 쓰지 않는 것: 배경 설명, 일반론적 모범 사례, 이미 다른 곳(코드·문서·다른 구성요소)에 있는 내용 — 마지막은 포인터로 대체한다.
- 판단이 갈리는 지점에만 판정 기준을 한 줄 붙인다.

### 제3원칙 — 경계를 명시한다

목적이 미치는 범위와 미치지 않는 범위를 함께 서술한다. **정본은 description이다** — 로드·위임 판정이 description만으로 이뤄진다.

- 본문 `## 경계`의 비대상은 description의 비대상과 같은 집합이고, 처리처만 덧붙인다. 본문에서 비대상을 새로 만들지 않는다.
- 사용자 명시 호출 전용 구성요소는 로드 판정이 없으므로 description에 비대상을 적지 않는다 — 이때는 본문 `## 경계`가 정본이다.

### 제4원칙 — 검증 가능해야 한다

- 구성요소가 목적을 실제로 달성하는지, 그 목적을 위한 요청에 적절히 호출되는지 검증할 방법을 서술한다.
- 실제 요청·위임을 돌려야 확인되는 항목은 `(시험)`으로 표시한다. 표시 없는 항목은 그 자리에서 파일 대조·명령 실행으로 확인되는 것이다.
- `## 검증` 절을 둘 수 없는 구성요소(settings.json·CLAUDE.md)는 해당 reference의 검증 절이 분모다.
- 구성요소를 추가·수정하면 표시 없는 항목을 수행하고, 결과를 커밋 메시지에 `검증: <수행>/<전체>`로 남긴다. 건너뛴 항목이 있으면 이름과 이유를 응답에도 낸다. `(시험)`은 변경과 관련된 것을 돌렸을 때만 항목 이름을 덧붙인다.

### 제5원칙 — 호출 조건은 자신이 정의한다 (description)

- 구성요소는 자신이 언제 호출될지를 description에 서술한다.
- 비대상의 처리처는 이름만 적고, 그 구성요소의 호출 조건은 복제하지 않는다.

### 제6원칙 — 고정할 것과 열 것을 구분한다

구성요소의 각 항목을 **입력이 달라져도 정답이 같은가**로 판정한다.

- **정답이 같다** → 고정한다. 형식·필수 항목·범위·금지가 여기 속한다. 수단은 어겨도 되는지로 정한다 — 어겨도 되면 본문 문장, 안 되면 훅·permissions·tools allowlist.
- **정답은 다르나 판정 축이 같다** → 축만 고정하고 결론은 연다. 기준표·체크리스트로 쓴다.
- **축도 다르다** → 연다. 대신 산출물에 판단 근거를 함께 적게 해 사후에 검증되게 한다.

판정이 갈리면 열어두고 근거를 적게 한다 — 오적용이 불일치보다 비싸다.

열어둔 자리에 예시를 달지 않는다. 예시는 다른 입력에서도 그 형태를 복제하게 만들어 사실상 고정으로 작동한다.

열어둔 판단은 **수행 시점이 관측되게 한다.** 산출물에 드러나지 않는 판단은 수행 여부를 확인할 수 없어 발동하지 않는다 — 판단을 언제 하는지(어느 도구 호출·어느 단계 전인지)와 결과를 어디에 내는지를 함께 적는다.

응답에 내는 것은 **사용자가 그 자리에서 뒤집을 수 있는 판단**뿐이다. 이미 끝난 일의 자기 신고는 산출물(계획 파일·커밋 메시지)에 남긴다 — 뒤집을 수 있는지는 그 판단 뒤에 사용자가 개입할 동작이 오는가로 가른다.

## 배치 기준

| 조건 | 배치처 |
|---|---|
| 모든 세션에서 항상 필요한, 변경 빈도 낮은 지침·사실 | CLAUDE.md (200줄 이하 유지, 멀티스텝 절차는 두지 않음) |
| 적용 조건이 작업 종류가 아니라 파일 경로·패턴 | `.claude/rules/` (frontmatter `paths:`로 해당 파일을 읽을 때만 로드) |
| 특정 종류의 작업에서 반복되는 멀티스텝 절차 | 스킬 (본문은 호출 시에만 로드) |
| 독립 컨텍스트가 필요한 작업 — 중간 출력이 커서 격리하거나, 병렬로 돌리는 조사·검토 | 에이전트 |
| 모델 판단에 의존하면 안 되는 결정적 강제 — 포맷팅, 검증, 차단 | 훅 (settings.json) |
| 사용자가 명시 호출할 때만 실행할 절차 | 스킬 + `disable-model-invocation: true` |

CLAUDE.md에서 절차로 자라난 내용은 스킬로 옮긴다.

## 피드백 반영

- 하네스 검토·수정 시 `.claude/FEEDBACK.md`의 미해결 기록을 먼저 확인한다.
- 사용자가 요청하거나 같은 구성요소에 기록이 3건 이상 쌓이면 개선을 제안한다.
- 개선에 반영한 기록은 FEEDBACK.md에서 삭제한다.

## 모델 교체 재검토

`.claude/model-review.txt`(`<계열> <모델ID> <상태>`)에 `pending`인 계열이 있으면 수행한다. 범위는 SessionStart 훅 알림이 지정한다.

- **opus 계열 교체 — 하네스 전체**: 모든 구성요소를 위 6원칙·배치 기준과 대조하고, 모든 구성요소의 `(시험)` 항목과 아래 모델 종속 항목을 수행한다. 부작용이 있는 시험(실 API 쓰기·병합)은 수행 전에 사용자에게 묻는다.
- **그 외 계열 교체 — 알림에 나열된 에이전트만**: `model:`이 그 계열인 에이전트에 대해 항목 1과, 그 에이전트에 관한 항목 2, 그 에이전트의 `(시험)` 항목을 수행한다.

모델 종속 항목:

1. `.claude/agents/*.md`의 `model:` 별칭 — 별칭이 가리키는 세대가 바뀌었는지 확인하고 작업 난이도에 맞는지 다시 판정한다.
2. `.claude/FEEDBACK.md`의 미해결 기록 — 새 모델에서도 재현되는지 확인해 보고한다.

완료하면 해당 줄을 `reviewed`로 바꾼다.

## 경계

- 대상: `.claude/**`와 CLAUDE.md, 그리고 이 플러그인 소스(`${CLAUDE_PLUGIN_ROOT}`)에 대한 추가·제거·수정·검토·관리. 프로젝트 `.claude/hooks/`에 복사된 `skill-required.py`·`write-scope.py`와 `templates/rules/`에서 복사된 rules는 플러그인이 정본이다 — 고칠 때 플러그인을 먼저 고치고 복사본을 맞춘다. 프로젝트 고유 값은 구성요소 본문에 넣지 않고 CLAUDE.md `## 프로젝트 사실`(항목 표는 `references/claude-md.md`) 또는 구성요소 전용 오버레이(`.claude/trello.md`·`.claude/merge-gates.md`·`.claude/write-scope.json`)에 둔다.
- 비대상: 하네스를 사용해 수행하는 일반 개발 작업, `docs/**` 등 하네스 밖 문서.

## 검증

- 목적 달성: 변경한 구성요소가 위 6원칙과 배치 기준을 각각 대조한다. 본문에 명령·스크립트를 적었으면 실제로 실행해 본다.
- 고정·열기: 변경한 항목마다 제6원칙 판정을 적용하고, 고정한 항목은 수단(본문 문장·훅·tools)이 강도에 맞는지, 열어둔 판단은 수행 시점과 결과가 산출물에 드러나는지 대조한다.
- 규격: `claude plugin validate .claude/skills`가 통과해야 한다. 스킬·에이전트·settings를 고친 뒤 실행한다. 플러그인을 고쳤으면 `claude plugin validate ${CLAUDE_PLUGIN_ROOT}`도 통과해야 한다.
- 복사본 일치: 플러그인 `hooks/skill-required.py`·`write-scope.py`를 고쳤으면 프로젝트 `.claude/hooks/`의 복사본과 `diff`가 비어야 한다.
- 프로젝트 사실 참조: 플러그인 구성요소가 `프로젝트 사실 \`<항목>\``으로 참조하는 항목이 `references/claude-md.md`의 표에 전부 있어야 한다 — `grep -rho '프로젝트 사실 \`[^\`]*\`' skills agents | sort -u`로 대조한다.
- 충돌: 변경한 구성요소가 CLAUDE.md·다른 구성요소의 지시와 모순되지 않는지 대조한다. 같은 대상을 정하는 문장이 두 곳에 있으면 한쪽을 정본으로 남긴다.
- (시험) 호출 적절성: 이 스킬은 하네스 관련 요청(추가·수정·검토 등)에서 로드되고, 일반 개발 요청에서는 로드되지 않아야 한다.
